# HandkerSkinsProject

Бот для отслеживания и автоматической покупки скинов CS2 на площадке [market.csgo.com](https://market.csgo.com) по выгодной цене, с уведомлениями в Telegram.

## О проекте

Идея простая: на бирже периодически появляются лоты, выставленные заметно дешевле их реальной рыночной стоимости — например, продавец случайно занизил цену. Бот слушает поток событий площадки в реальном времени, фильтрует такие лоты по заданным правилам и — если найдено совпадение — пытается их выкупить, а после отправляет отчёт в Telegram.

Это учебный/пет-проект, написанный для практики со Spring Boot, WebSocket-интеграциями и работой с внешним REST API в реальном времени.

## Как это работает

1. **WebSocket-клиент** подключается к live-каналу площадки (`public:items:730:rub` через протокол Centrifugo) и получает события о новых и изменённых лотах в реальном времени.
2. Для каждого события бот резолвит `name_id` в человекочитаемое название предмета через локальный справочник (обновляется раз в сутки).
3. Цена лота сравнивается с двумя закэшированными значениями:
   - **top order** — текущий лучший ордер на автопокупку по этому предмету;
   - **минимальная цена** этого предмета на рынке прямо сейчас.
4. Если лот стоит совсем немного выше top order (узкое "окно" в 0.5-8%, зависит от ценового диапазона), а разница между top order и реальной минимальной ценой рынка достаточно большая (от 20%+) — лот считается кандидатом на покупку.
5. Перед покупкой бот проверяет закэшированный баланс аккаунта (обновляется каждые 15 секунд + сразу после любой попытки покупки) — если денег не хватает, покупка не запускается.
6. Покупка выполняется через REST API площадки; результат (успех/неудача) вместе с ценой, спредом и временем ответа API отправляется в Telegram.
7. Отдельный REST API (`/api/v1/skins/...`) позволяет управлять списком отслеживаемых скинов: массовый импорт по ценовому диапазону, ручная синхронизация цен, ручной тестовый эндпоинт для проверки покупки без ожидания реального кандидата из потока.

Все входящие/исходящие цены обрабатываются в рублях, привязаны к рублёвому стакану площадки.

## Технологии

- **Java 21+** (используются виртуальные потоки — `Executors.newVirtualThreadPerTaskExecutor()` для покупок, чтобы не блокировать чтение WebSocket)
- **Spring Boot** (Web, Data JPA, Scheduling)
- **PostgreSQL** + **Flyway** — хранение отслеживаемых скинов и истории цен, миграции схемы
- **Hibernate / JPA**
- **Java-WebSocket** — низкоуровневый клиент для подключения к live-каналу площадки
- **Jackson** — разбор JSON от WebSocket и REST API
- **TelegramBots (Java)** — отправка уведомлений
- **Lombok**
- **Maven**

## Возможности

- Живое отслеживание цен на CS2-скины через WebSocket, без поллинга
- Настраиваемые по ценовым диапазонам пороги маржи и спреда
- Массовый импорт скинов в отслеживание по диапазону цен, с фильтрацией нерелевантных категорий (стикеры, кейсы, музыкальные наборы и т.д.)
- История цен по каждому отслеживаемому скину
- Проверка баланса перед покупкой с защитой от гонки при нескольких кандидатах подряд
- Режим dry-run — вся логика работает как обычно, но реальный запрос на покупку не отправляется
- Ручной тестовый эндпоинт для проверки покупки конкретного лота в обход основного потока
- Уведомления в Telegram о каждой попытке покупки (успех и неудача) и об аномальных изменениях цены

## Ограничения

Честно о том, чего бот пока не умеет и на что стоит рассчитывать:

- **Это не низколатентный снайпинг-бот.** Без выделенного сервера рядом с инфраструктурой площадки и без "прогретого" HTTP-соединения реальный ответ API на покупку может занимать от ~100 мс до нескольких секунд — против ботов, которые физически стоят в том же дата-центре, шансы выиграть гонку за конкретный лот невысокие.
- **После каждого переподключения WebSocket есть "слепое окно" около 60 секунд**, в течение которого все события намеренно игнорируются (чтобы не среагировать на устаревший снимок состояния при реподписке). Реальные новые лоты в этот момент могут быть пропущены безвозвратно — Centrifugo не досылает пропущенные сообщения.
- **Фильтр кандидатов достаточно строгий** и рассчитан на редкие, но выгодные аномалии — не стоит ожидать частых срабатываний; в спокойные периоды бот может не находить кандидатов часами.
- **Таймаут ≠ гарантированная неудача.** Если ответ API на покупку не пришёл за отведённое время, бот считает покупку неудавшейся — но по факту операция иногда всё же успевает пройти на стороне площадки. Стоит время от времени сверяться с инвентарём/историей сделок, а не полагаться только на статус в уведомлении.
- **Нет ограничения на суммарные траты** (дневной/часовой лимит) — единственная защита сейчас — проверка текущего баланса перед каждой покупкой.
- Кэши баланса, топ-ордеров и минимальных цен обновляются с фиксированным интервалом (секунды), решения принимаются на почти актуальных, но не идеально live данных.
- Тестировался в первую очередь в dry-run режиме; боевой режим стоит включать осознанно и под присмотром.

## Запуск проекта

Для запуска понадобятся:

- Java 21+
- PostgreSQL (локально или удалённо) — создать пустую базу, схема накатится автоматически через Flyway при первом запуске
- Собственный Telegram-бот (токен и chat id) — создаётся через [@BotFather](https://t.me/BotFather)
- Ключ API от собственного аккаунта на market.csgo

Чувствительные значения не хранятся в репозитории — они подставляются через переменные окружения:

| Переменная | Назначение |
|---|---|
| `DB_PASSWORD` | пароль от вашей PostgreSQL-базы |
| `TELEGRAM_BOT_TOKEN` | токен вашего Telegram-бота |
| `TELEGRAM_CHAT_ID` | id чата, куда слать уведомления |
| `MARKET_API_KEY` | ключ API вашего аккаунта на market.csgo |

Задайте их в переменных окружения системы или в конфигурации запуска вашей IDE, после чего можно собирать и запускать проект стандартно через Maven:

```
mvn spring-boot:run
```

По умолчанию `market-csgo.buy.dry-run=true` — реальные покупки отключены, весь пайплайн можно безопасно протестировать без риска для баланса.

## Дисклеймер

Проект взаимодействует с реальным аккаунтом и реальными деньгами при выключенном dry-run режиме. Используется на свой страх и риск.
